# Дневник сна Hybrid 2.0

Один веб-интерфейс для PWA и Android WebView. В Android-оболочке небольшой нативный сервис отслеживает системное событие `ACTION_USER_PRESENT`; сайт отвечает за календарь, анкеты, аналитику и экспорт.

## Что уже реализовано

- Адаптивный тёмный интерфейс на русском языке.
- PWA: установка на главный экран, офлайн-кэширование оболочки сайта.
- Локальная база IndexedDB: календарь, ночные записи, ответы и заметки.
- Анкета: самочувствие, выспался ли, энергия, стресс, пробуждения, поздний кофеин, дневной сон и заметки.
- Аналитика по завершённым ночам и личный ориентир по ночам, после которых пользователь отметил, что выспался.
- Экспорт в XLSX (листы «Дневник» и «Анализ») и резервная копия JSON с импортом.
- Android WebView использует тот же каталог `web/`, без второй копии HTML/CSS/JS.
- Android foreground service начинает работу только по нажатию пользователя и показывает постоянное уведомление.
- Системное событие разблокировки до 2 часов переносит старт на момент разблокировки; ровно через 2 часа и позже завершает ночь.
- Очередь нативных событий сохраняется на Android до подтверждения веб-интерфейсом, чтобы не потерять событие, если страница была закрыта в момент разблокировки.

## Как перенести проект в существующий репозиторий

Если репозиторий уже содержит предыдущую Android-версию дневника, не загружай этот архив внутрь дополнительной папки. Распакуй его так, чтобы `app/`, `web/`, `.github/`, `build.gradle.kts` и `settings.gradle.kts` оказались прямо в корне репозитория. Полностью замени старую папку `app/` и корневые Gradle-файлы, а старые workflow-файлы, в частности `.github/workflows/build-apk.yml`, удали. Оставь только новые `android.yml` и `deploy-pages.yml`, чтобы старые сборки не запускались параллельно.

## Как опубликовать сайт на GitHub Pages

1. Загрузить содержимое этого проекта в корень репозитория, сохранив папки `web`, `app` и `.github`.
2. В GitHub открыть **Settings → Pages**.
3. В разделе **Build and deployment** выбрать **GitHub Actions**.
4. Запустить workflow **Deploy Sleep Journal PWA** во вкладке Actions или отправить commit с изменениями в `web/`.
5. После успешного workflow сайт появится по адресу `https://<владелец>.github.io/<имя-репозитория>/`.
6. На Android открыть этот адрес в Chrome и выбрать **Установить приложение** / **Добавить на главный экран**.

PWA, открытая непосредственно в Chrome, не получает системное событие разблокировки Android. В ней запись завершается вручную. Для автоматического определения разблокировки нужно открыть тот же веб-интерфейс через Android-компонент (APK).

## Как собрать Android APK

Workflow `Android Hybrid Build` запускает unit-тесты и `:app:assembleDebug`. APK публикуется как artifact `sleep-journal-hybrid-debug`.

Сборка использует JDK 17, Gradle 9.5.0, Android SDK 36 и AndroidX WebKit 1.18.0. Gradle Wrapper намеренно не используется: GitHub Actions устанавливает конкретную версию Gradle через `gradle/actions/setup-gradle`.

Локально при наличии Android SDK и Gradle 9.5.0:

```bash
gradle --no-daemon :app:testDebugUnitTest :app:assembleDebug
```

## Логика автоматического сна

- Нажатие «Я ложусь спать» создаёт запись в IndexedDB и запускает нативный foreground service.
- Сервис регистрирует динамический `BroadcastReceiver` для `Intent.ACTION_USER_PRESENT`.
- Разблокировка раньше двух часов сдвигает фактическое начало записи на время разблокировки. Если событие пересекает полночь, ночь переносится на новую локальную дату.
- Первая разблокировка ровно через два часа или позже завершает запись.
- Нативные события сохраняются в очереди SharedPreferences и передаются веб-интерфейсу при следующем открытии/возвращении в приложение.

Android сообщает факт появления пользователя после пробуждения устройства (например, когда keyguard снят), но не сообщает, вводил ли пользователь пароль, PIN, биометрию или просто провёл по экрану. Для ожидаемого поведения на устройстве должна быть настроена блокировка экрана. Сервис не является гарантированным системным трекером: производитель устройства может ограничивать фоновые процессы/автозапуск, а принудительная остановка приложения, перезагрузка или остановка сервиса могут прервать наблюдение. Постоянное уведомление показывает активную запись.

## Локальные данные и приватность

- Веб-версия хранит дневник в IndexedDB того браузера, в котором её открыли.
- Android WebView имеет отдельное локальное хранилище от Chrome. Поэтому PWA в Chrome и Android-оболочка не синхронизируют записи автоматически. Для переноса между ними используй резервную копию JSON (экспорт/импорт) или Excel.
- Серверной базы и отправки дневника в сеть в этой версии нет.
- Очистка данных сайта/WebView или удаление приложения может стереть базу. Делай резервные копии.

## Проверки и ограничения текущей сборки

- Unit-тесты покрывают порог менее 2 часов, ровно 2 часа, более 2 часов и изменение системного времени назад.
- Веб-JavaScript проверяется синтаксически, XLSX-пакет можно проверить открытием в Excel/LibreOffice.
- Полноценную сборку APK необходимо подтвердить в GitHub Actions, так как локальная среда разработки здесь не содержит Android SDK и Gradle.
- Поведение `ACTION_USER_PRESENT`, энергосбережение и особенности прошивки нужно проверить на реальном Android-устройстве.
